# HealthcareDirectory.my

This is a static website for <https://healthcaredirectory.my>: a clinic directory and health awareness guides for Kuala Lumpur. The published site is plain HTML, CSS and JavaScript with no runtime dependencies. The HTML pages are generated from content files by a small Node script in `tools/build/` (Node 18+, no npm packages).

## Structure

```
index.html                     Home: hero search, awareness, clinic directory, articles, neighbourhoods, FAQ
clinics/                       Clinic directory + one page per clinic (MedicalClinic schema, map, hours)
articles/                      Blog index + one folder per article (Article/MedicalWebPage schema)
about/  contact/  privacy/     Editorial policy, contact & list-your-clinic, PDPA notice
search/                        Full search results page (noindex); header search shows instant results
404.html                       Not-found page (noindex)
assets/css/site.css            All styles (design tokens at the top)
assets/js/site.js              Progressive enhancement: filters, "open now" (GMT+8), search, TOC, share
assets/search-index.json       Search index generated by the build (loaded only when someone searches)
assets/img/                    Self-hosted Pixabay photos: WebP at 480/960/1600w + 1200×630 OG JPGs
sitemap.xml  robots.txt  site.webmanifest  favicon.*
tools/                         Build script, image helper and SEO checker (not part of the site)
```

URLs are clean folders (`/clinics/<clinic-slug>/`). The site works on any static host, such as Netlify, Vercel, Cloudflare Pages, GitHub Pages or S3. Point the host's custom 404 at `/404.html`. If you deploy the whole repo, exclude `tools/` and `README.md` from the published files.

## Local preview

```bash
python -m http.server 8765
```

Then open <http://localhost:8765>.

## Deploy (Cloudflare Pages)

The site is hosted on Cloudflare Pages (project `healthcaredirectory`), and DNS for `healthcaredirectory.my` is on Cloudflare.

```bash
node tools/build/build.mjs
node tools/deploy.mjs
```

`tools/deploy.mjs` copies only the public files into `.deploy/` and runs `wrangler pages deploy`. Pass `preview` to get a `*.pages.dev` preview link without touching production. The build also writes the Pages config files:

- `_headers`: caching and security headers.
- `_routes.json`: limits the redirect function to pages, so static files don't invoke it.
- `functions/_middleware.js`: 301-redirects `www.healthcaredirectory.my` to the bare domain.

## Before launch

- **Newsletter:** set `data-endpoint` on `.js-newsletter` forms to a Formspree, Buttondown or similar URL. Until then the form tells visitors sign-ups open soon.
- **Contact email:** `hello@healthcaredirectory.my` is used across the site (`SITE.email` in `tools/build/lib.mjs`). Create the mailbox, or set up forwarding.
- **Clinic details:** listings can go live with incomplete details (the page then shows “Listing in progress” and asks visitors to call ahead). Confirm hours and phone numbers with each clinic.
- **Search Console:** verify the domain and submit `https://healthcaredirectory.my/sitemap.xml`.

## Editing content

The HTML files are generated, so edit the sources in `tools/build/`, not the HTML. Hand edits to generated pages are overwritten on the next build.

| File | What it holds |
|---|---|
| `clinics.mjs` | Clinic details: address, phone, hours, services, panels, FAQs, and the area filters |
| `articles-news.mjs` | News-based health articles |
| `articles-guides.mjs` | Everyday guides and clinic guides |
| `seo.mjs` | Search titles (60 characters or fewer) and meta descriptions (155 or fewer). The build fails if one is too long. |
| `pages.mjs` | Page templates: home, clinics, clinic page, blog, article |
| `static-pages.mjs` | About, Contact, Privacy and 404 |
| `lib.mjs` | Shared `<head>` (meta tags, Open Graph), header, footer and the responsive image helper |
| `search.mjs` | Search index and `/search/` page. `SYNONYMS` maps Malay and everyday words (for example *denggi* or *darah tinggi*) to topics. |
| `build.mjs` | Builds every page, plus `sitemap.xml`, `robots.txt` and the search index |

Rebuild, then check every page for broken links, invalid JSON-LD, missing alt text and title or description lengths:

```bash
node tools/build/build.mjs
python tools/check.py
```

### Adding an article

Copy an entry in `articles-news.mjs` or `articles-guides.mjs` and give it a new `slug`. Add its title and description to `seo.mjs`, then rebuild. The new article appears on the blog, in the sitemap and in "Keep reading" automatically. Inside article HTML, `{{img:name|Alt text}}` inserts a responsive image.

### Adding a clinic

Add an entry to `CLINICS` in `clinics.mjs` (a commented template at the top lists every field). Only `slug`, `name` and `areaLabel` are required: anything missing is hidden or replaced with a “call to confirm” note, so a clinic can go live with partial details. Add a network (for example CareClinics) to `NETWORKS` to group branches. Optionally add a custom title and description to `seo.mjs`, then rebuild. Each clinic gets a page, a directory card, an area filter, a footer link and structured data.

### Adding an image

```bash
pip install pillow
python tools/add-image.py path/to/photo.jpg image-name
```

This writes the WebP sizes and the social-share image to `assets/img/` and registers them in `tools/build/imgmeta.json`. You can then use `image: 'image-name'` in content.
